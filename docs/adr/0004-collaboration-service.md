# ADR-0004：双人共同课堂的协作服务边界

日期：2026-10-06。范围：INVITE-01 / SYNC-01 / CHAT-01 的在线协作前置依赖。

状态：**设计已定、本地链路与在线服务均已实现**——协作服务的地址/协议/部署方案见下文 §1，邀请/成员/事件/消息的权威存放与 HTTP 链路已按该设计实现；在线唯一登记、本人凭据认证、独立服务进程与结构化场景同步见 [ADR-0005](0005-online-collaboration-service.md)，自动化双客户端链路已在本机验证（见 `scripts/collab-two-client-link.mjs`）。**双设备真人联调（COLLAB-EVAL-01）仍未执行**，不据此宣称在线已通。

## 1. 地址 / 协议 / 部署方案

- **地址**：协作服务与本地学习服务是两个进程。本地学习服务继续只监听
  回环地址（`127.0.0.1`），不直接开放给远端；协作服务是独立可部署进程，
  承担 UID 唯一性登记、本人认证、邀请与成员校验、共享快照、房间状态和
  实时事件分发（《规划书》7.6）。本机开发与回归用 `http://127.0.0.1:<端口>`
  的同机协作服务；跨设备联调时两台客户端连同一个协作服务地址，
  该地址与版本写入联调记录（COLLAB-EVAL-01），不在代码里写死远端地址。
- **协议**：与本地学习服务相同的信封与合同——成功 `{ ok: true, data }`、
  失败 `{ ok: false, error }`（`StudyErrorPayload`：code + 中文文案 + pending
  标记）；邀请/消息/事件的命令形状复用
  `packages/study-contracts/src/classroom-collaboration.ts`，
  判定复用 `packages/study-domain/src/collaboration.ts`，
  不另立第二套协作方言。传输层当前为 HTTP 轮询（读取：按 `afterSeq` 取
  `(afterSeq, tailSeq]` 增量；写入：带 `requestId` 幂等重试），
  实时推送通道（若后续需要）另立 ADR，不在本轮引入长连接。
- **部署**：协作服务拥有共享房间的权威状态（邀请/成员/事件/消息），
  各端本地服务拥有个人学习记录（草稿/答案/判分/错题/掌握），
  按《规划书》7.6 划分归属，不把两台设备的 SQLite 当作共同权威。
  协作服务数据与用户项目数据分离存放；卸载本地应用不删除协作服务数据，
  跨设备身份恢复走 UID 登记/认证，不走项目文件拷贝。
- **认证**：知道 UID 不能登录——成员身份由服务端按认证会话绑定，
  请求体自报的 UID 与会话绑定的 UID 不一致即拒绝
  （`assertCollabAdmission` 的 `collab_identity_mismatch`）。
  UID 不是密码或登录凭据（ADR-0002 同源）。

## 2. local_link 的已有合同（历史基础，可本机回归）

- 离线稳定 UID、个人入口查看/复制、旧 learner ID 映射（ADR-0002）；
- 个人房间：冻结课程版本/摘要、共享快照、教师租约、会话绑定（ADR-0003）；
- 正式互动公共投影：参数/关系/排序三种定义的公开形状，
  正确目标（`to`/`correctOrder`）不进快照；
- 协作权威存放（迁移 30）：`collab_registrations`（UID 登记占位，`authority`
  固定 `local_link`）、`collab_invitations`（邀请生命周期）、
  `collab_rooms`（共享房间：课程版本/摘要、当前场景、revision，
  状态 `ready → active`）、
  `collab_room_members`（成员与准备状态）、`collab_room_events`
  （权威单调序号事件）、`collab_room_messages`（课内消息，唯一去重键）、
  `collab_command_receipts`（各命令幂等收据）；
- 协作 HTTP 链路：`/api/study/collab/registration`（登记/查询本人登记）、
  `/api/study/collab/invitations`（发起/表态/撤销/按房间查询）、
  `/api/study/collab/rooms`（建房/开始共同课堂/成员准备状态/读取房间与成员）、
  `/api/study/collab/messages`（追加/按游标读取）、
  `/api/study/collab/events`（追加/按游标读取），响应合同见
  `apiResponses.collab*`；**写入与读取**的身份一律由会话绑定：请求体自报他人 UID
  即拒绝，且房间存在时只有成员能读取房间/成员/消息/事件（非成员 `not_room_member`）。
  开始共同课堂由 `start` 动作触发（只有房主、成员恰为邀请双方且都已 ready 才把房间置
  `active`，复用 `assertCollabRoomStartable`）；
  房间与有效邀请绑定唯一的邀请双方，邀请、接受及显式建房均复核归属、ready 状态与
  双人名额；外人不能借已有 roomId 加入，也不能抢占尚未建房的邀请预留。
  `left` 成员保留历史但立即失去读取、新写入及旧收据重放权限，不能自行改 ready 重入；
  房主退出会结束房间。读写均要求项目身份与代次，项目重开后的旧请求拒绝。
  所有拒绝均在事务内保留原邀请、成员和消息事件历史；
- 协作合同与判定：`packages/study-contracts/src/classroom-collaboration.ts`
  定邀请/房间/成员/消息/事件的命令与结果形状，
  `packages/study-domain/src/collaboration.ts` 定发起/表态/撤销/写入/序号/
  游标/准备页/入场/快照/执行权的纯判定，存储级回归见
  `tests/classroom-collaboration-storage.test.ts`，
  纯判定回归见 `tests/classroom-collaboration.test.ts`。
- `/workbench/collab` 已接本机登记、邀请、准备、开始及讨论界面，按 5 秒轮询；
  切房清空旧游标、完整未确认命令重试与失败草稿保留均遵循同一合同。
  该早期 local_link 阶段的场景事件只记录摘要；当前共同课堂面板已改为在线优先，实际推进经 ADR-0005 的 scene-sync，未认证/配置时明确不能联网邀请。

上述链路都在**本地服务进程内**运行（同一 SQLite、同一会话），
用于把「两端见面时互相承认什么」写成可回归的合同；它没有跨进程网络传输、
没有第二台设备、没有真实认证，因此**不等于在线协作已通**。

上述 1—5 已在 [ADR-0005](0005-online-collaboration-service.md) 落地为独立协作服务
`apps/collab-service` 与受控客户端链路（本机自动化双客户端验证覆盖，见
`scripts/collab-two-client-link.mjs`）。`collab_registrations.authority` 仍对本机链路
写 `local_link`，只有经独立服务凭据认证的在线登记才写 `online`；界面在未连接或未认证时
继续显示「不能联网邀请」。**在线部署与两位真人两台设备 COLLAB-EVAL-01 仍未验收。**

个人草稿、完整答案、判分、错题与掌握状态保留在本人本地服务，
共同课堂仅同步准备/已提交/待反馈等流程状态，不默认公开答案。
模型密钥、认证凭据、整个材料库及无关项目文件不进入共享快照、
聊天消息或房间事件。

## 不采用

- 把桌面回环服务直接开放给远端同学：破坏原生授权与控制凭据边界；
- 把两台设备的 SQLite 当作共同权威：跨设备事务不存在，
  回传采用带 UID、房间版本和幂等键的收据；
- 用 AI 同学讨论、单机双窗口或仅分享课程文件代替双人验收；
- 用「接口已存在」宣称在线已通：设计虽已定稿，在线部署与真人双设备验收仍未完成。

## 验收（联调时）

两位真人、两台物理设备、一节已发布课程，完成邀请至同课、双向文字交流、
独立作答与重连闭环；重复消息/教师动作/本人提交计数为 0，个人记录互相
污染数为 0。见待办 COLLAB-EVAL-01，外部门槛暂缓期间不虚构该证据。
