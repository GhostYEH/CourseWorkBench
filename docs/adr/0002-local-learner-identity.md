# ADR-0002：用户级离线 UID 与旧学习者分区映射

日期：2026-10-04。范围：规划 UID-01 的离线基础；在线登记、认证和跨设备身份恢复另行实现。

## 决定

本地服务在桌面已有 userData 目录维护独立 `learner-profile.json`，复用服务启动时可信 `--user-data` 参数与开发回退目录，不增加第二生产服务或新的身份路径 IPC。UUID v4 用作公开稳定标识，昵称采用 UID 与 revision 双前提 CAS。读取/首次创建/替换均严格校验；存在但损坏或未知版本不得当作缺失重新生成。

首次创建将已完整写入、fsync 的临时文件以硬链接 no-clobber 原子发布，竞争者读取胜出档案。昵称更新使用排他写锁、临时文件及原子替换。锁不能自动抢占，故障时优先保留原身份；崩溃后的遗留锁会阻止更名，需要核对后恢复。当前文件系统必须支持硬链接；不以可覆盖的非原子写入作为降级。

项目数据库 v19 增单用户绑定 `(projectId, sew:classroom:owner:v1) → UID`。经可信原生入口或已授权环境打开项目时建立本地绑定；有旧本人记录时记为 `legacy_local`，否则 `created_local`。旧记录缺少可认证 UID，因此该关系是一次本地迁移解释，不是历史身份或在线本人认证证明。原 Runtime 分区键、事件 ID、原始答案、评分和收据不改写。已绑定其他 UID 的项目拒绝打开，不重新归属；失败替换保留当前可用项目。

## 比较与迁移成本

- 把 UID 写入 `desktop-state.json`：会与主进程整对象配置写入冲突，需要同步修改窗口、最近项目和偏好写入；独立文件避免互相覆盖，保留原桌面配置结构。
- 每个项目创建独立 UID：虽然只需增加一列，却不能满足科目切换保持身份，后续共同课堂还需合并身份；不采用。
- 直接用 UID 替换 Runtime learnerKey：会改变 QuizSceneView 会话/草稿键和旧收据恢复，需要迁移 Runtime session、KV、课堂会话和所有消费者；映射层只增加一张表，原课堂协议与恢复路径保持兼容。
- 全部旧项目先要求在线认证：现有离线旧记录没有认证材料，且会阻断离线升级；本轮保留明确标记的本地迁移。M3 接入在线成员/认证时不能把该迁移映射作为远端认证凭据。

## 边界与验收

无项目 `/profile` 可查看/复制 UID 并改昵称，仍受应用会话、Host/Origin 认证。界面明确 `local_only`、不能邀请，UID 不是密码或登录凭据。在线身份登记、本人认证、邀请和实时协作仍未实现；后续已实现的本地单人房间另见 [ADR-0003](0003-classroom-room-authority.md)，不构成在线共同课堂。

数据库快照携带项目绑定，用户级身份文件不跟随项目导出。跨 profile 拷贝已绑定项目必须拒绝静默改绑；完整身份恢复、用户备份与共同课堂部署属于后续任务。测试使用临时 userData，禁止改写真实身份。验收覆盖独立进程 UID 一致、并发首次创建/CAS、昵称与科目切换、损坏/写入失败、v18 迁移原记录字节不变、备份绑定保留、跨 profile 拒绝和实际 Electron 个人页面交互。
