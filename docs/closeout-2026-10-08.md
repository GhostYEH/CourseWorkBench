## 已实现的软件行为

- 课程作者可录入项目定义，核对真实冻结来源陈述并明确声明语义审核后冻结。服务核验课程版本、知识/来源、每项任务与里程碑依据；本人席位绑定当前 UID，AI 席位由服务分配，客户端不能冒名。冻结后内容不可原位改写。
- 已审核 PBL 定义进入默认/自定义场景计划、正式课堂装配与恢复检查。稳定场景 ID 支持短 ID、长 ID、连字符及中文而不被计划规范化改名。课堂及 HTML 导出的公共骨架没有私有评分依据、成员 UID、草稿或交付记录。
- 正式课堂提供本人任务开启/更新、分任务草稿、正式交付和历史收据。SQLite 持久化并重建真实本人状态，重进可恢复最新草稿；草稿和 AI 贡献不计为本人正式交付。确定性检查与里程碑结论由服务执行，模型不能写入伪造的通过结论。
- 本人可选择自己的真实交付，向正式 AI 席位请求导师反馈、评价候选或贡献。实际配置走 `ModelConnectionRuntime`，先检验确认计划、有效 run、来源、已审核发布课程、冻结角色及共享预算，再派发 provider。导师反馈/贡献提示不带私有评分依据；评价只使用选中里程碑依据。候选保持私有，评价采纳和贡献确认需本人明确操作，均不改变确定性达成结果。
- 共享用量台账先保存调用结果，再写候选。同请求重试沿用原 requestId，不重复派发；未知外部结果保留预占。用户取消、项目切换、run/来源/版本变更通过实际 AbortSignal 和 watchdog 中止在途调用，迟到结果不写正式记录。已结算但未落库候选恢复必须重新核验原 run；新 run 不能批准旧结果补写，已保存的收据仍可幂等读回。
- 演练显式使用 demo 分区，最多 50 个动作，执行实际任务/交付检查；不写正式记录、不冒充 AI 角色。通用 runtime API 阻断绕过 PBL 专用服务的直接写入。

人工语义审核是操作者核对真实性与适用条件的声明，程序不自动证明任意文本语义正确。当前只有单一本人席位；多人项目、完整多角色演练和可视项目编辑不在本批次完成范围。
