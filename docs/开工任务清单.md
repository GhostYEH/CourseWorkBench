### 1.2 实施包的最低交付形态

每个任务应形成可独立审查的改动包，并在交付说明中写清：

1. 改动目标、相关源码边界、数据/IPC/HTTP 合同，以及与上游调用链的关系。
2. 输入、前置任务、迁移或来源登记要求；若上游文件被复用，更新 `docs/upstream-adaptation.md` 的路径、版本、许可和修改说明。
3. 成功路径、失败路径、权限边界和状态恢复的验收步骤；证据指向实际构建、运行记录、收据或人工检查结果。
4. 当前剩余限制、未验证环境和下一依赖任务。不要把本地开发启动、静态页面、模拟成功、目录包验证或部分测试描述为安装态或完整功能通过。

“适合委派”列只给出自然的所有权边界，实际拆分时仍需让每个工作包只有一个负责人；共享仓库中的工作者必须先检查其他改动，不得回退他人编辑。所有实现遵守 [代码质量约定](code-quality.md)：共享类型先进入 contracts，领域规则不依赖 UI/IO，SQLite 持有业务权威，渲染层经受限 preload/DTO 通信。

任何真实模型/provider 请求都须先经过最小凭据、来源/授权、预算、截止时间和取消守卫，包括 PLAN-01 的模型计划候选、LESSON-02 的生成、连接检测、Director/教师以及后续媒体任务。M2 的 guard 工作包是共享实现的交付位置，不是允许更早任务无守卫调用的例外；当前采用人工/固定输入的路径不据此宣称模型能力通过。

来源规则按用途应用：正式学科内容必须经过证据准入；无学科内容的最小连接检测不依赖课程材料审核，仍须受凭据/授权/预算/取消约束；检索和抽取只产出材料或候选，不获得正式发布权限。guard 不能造成“没有已核实知识就无法获取资料或测试连接”的依赖循环。

## 2. 开工基线与当前门槛

产品基线为 Windows x64 Electron 单机备考工作台，OpenMAIC 固定本地版本作为学习空间主要复用来源，桌面壳负责原生权限与随包服务生命周期，学习服务持有领域逻辑和 SQLite。事实类内容须关联用户可定位的来源；AI 只产生候选；真实本人作答与 AI 演示分区保存。运行时、课程编辑和扩展后端的最终边界以规划书与架构决定为准。

目前不能宣称 M0 独立环境签核通过：固定三场景已接通真实上游渲染器、播放引擎及 SQLite 测验/互动提交链路，原 `ClassroomSurface` 的页面加载/重试/取消与 Stage 显示准入分支已复制并实际接线。持久教师会话、已审核讲解、白板/聚焦/激光笔、草案场景/元素编辑和 M1 来源链路已有实现；完整 Director/编辑器、互动/PBL/媒体生成仍保留。PACK-02 独立环境及当前源码目录包/安装验收未通过，不代表 M0 或 M1 整体通过。当前证据及真实剩余工作见待办和上游适配记录。

## 11. 执行与状态更新规则

- 每个实施包先核对当前源码、合同和上游实际调用方，再改动；不因规划文档猜测接口，也不搬回已删除的历史报告。
- 任务并行前先确定共享文件所有权和 API/DTO/schema；主进程权限、领域判定、SQLite 事务与 iframe UI 不由一个模糊的“课堂接入”包一并承担。
- 使用项目规定的构建和验证入口。生产 HTTP 验收必须由当前源码生成的 learning 产物支持；Electron 目录包和安装包的结论注明各自范围。
- 实现完成后做独立只读审查；审查结果不能由实现者自述代替。发现缺陷先修复并重新验证对应门槛。
- 仅在实现和对应验收均通过后更新待办及 JSON `status/evidence`。局部测试、计划完成、演示录屏或未经干净环境验证的安装包都不是完整阶段证据。
- 每次只推进依赖已满足且可验收的工作包；阻断要写出复现条件、影响面、尝试结果和下一步，不填猜测工期或虚构测试成绩。
