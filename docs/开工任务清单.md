# 开工任务清单与验收门槛

版本：v0.6；更新：2026-10-06（完成子项与剩余验收复核）。本文将 M0—M4 定义为“一个真实学科单元的备考闭环”阶段，保留 35 个既有里程碑 ID，并补充 CLASS-02 的演示/正式审核分区任务。它们是执行路线，不是 OpenMAIC 的完整能力清单；最终产品还必须逐项实现并验收 [85 项必需能力](openmaic-feature-parity.json)。阶段通过、打包验证或测试数量都不能单独代表最终完成。

本清单不提供未经实际试验支持的工期估算，也不把规划状态写成完成状态。每项只有在实现、对应验收和证据记录都成立后，才可按[待办事项](待办事项.md)中的规则收窄或移除。产品目标与领域合同见[规划书](规划书.md)，OpenMAIC 能力解释与批次背景见[深度剖析与全功能对齐](OpenMAIC深度剖析与全功能对齐.md)，架构和技术边界见[Electron 开发设计](Electron开发设计.md)及[架构决定](adr/0001-architecture-baseline.md)，上游实际采用文件与许可见[上游适配记录](upstream-adaptation.md)。

## 1. 范围、阶段关系与通用交付规则

2026-10-04 执行约束：按用户要求持续推进 M1—M4，完成约定范围后统一交付。真实科目材料/人工金标准和双设备真人走查由用户暂缓；软件实现、本机验证和复盘继续。暂缓项保留未签核，不用演示或单机双窗口替代。

当前基于 HEAD `9b74a25` 及其后本地未推送的协议 3/4 公共教学批次核对：离线 UID、个人房间/教师租约、正式参数/关系/排序互动、激光笔撤回/回放、人工反馈复习、课程编辑/候选审核、静态导出、项目课程库及独立在线共同课堂软件链路（含已审核陈述公共讲解、真实元素标记与公共白板文字/公式/图形及动作编排）已落地。下表删除线只标记已实现且有对应回归的子包；未划线部分继续实施或验收，任务 ID、输入依赖和验收门槛保留。证据以[收尾记录](closeout-2026-10-06.md)、[规划复核](规划书.md)和[剩余待办](待办事项.md)为准，不表示 M0—M4 整体通过。旧委派模型和交接要求是当时记录，后续委派以本次用户要求及适用 AGENTS.md 为准。

### 1.1 两条相关但不同的完成线

| 完成线 | 包含内容 | 通过后仍未证明 |
| --- | --- | --- |
| M0—M4 备考闭环 | M0 安装态固定课堂基线；M1 来源/工作台；M2 正式课程、教师、作答和基础互动；M3 同学、错题、复习、预算与恢复；M4 交付、量化评测和演示 | OpenMAIC 的完整编辑器、所有课堂场景、PBL、所有模型/媒体供应商、导入导出和部署形态均已实现 |
| JSON A—F 最终能力对齐 | `openmaic-feature-parity.json` 中 85 个有 ID 的 required feature，逐项核对实现状态与验收证据 | 教学效果或提分结论；这需要独立研究设计 |

M0 的固定课堂只要求一份来源登记并审核过的幻灯片、一项测验和一个互动场景。它不是四类场景，更不包含 PBL 完整能力。PBL 场景生成属于 B 批次 OMA-006；PBL 场景执行相关能力属于 C 批次 OMA-046、OMA-047、OMA-048、OMA-049。M0 通过不改变这些能力的状态。

JSON 的 phase A 有 **0 个 feature ID**。A 是跨批次技术前置工作：厘清真实调用链、身份/权限/数据合同与运行时扩展点，并建立四类 Scene（幻灯片、测验、互动、PBL）的基本挂载能力，供后续批次接入；这项技术子集不新增虚构的 OMA ID，也不表示完整 PBL 已实现。PBL 场景生成由 B 批次 OMA-006 跟踪，PBL 场景执行由 C 批次 OMA-046、OMA-047、OMA-048、OMA-049 跟踪。

### 1.2 实施包的最低交付形态

每个任务应形成可独立审查的改动包，并在交付说明中写清：

1. 改动目标、相关源码边界、数据/IPC/HTTP 合同，以及与上游调用链的关系。
2. 输入、前置任务、迁移或来源登记要求；若上游文件被复用，更新 `docs/upstream-adaptation.md` 的路径、版本、许可和修改说明。
3. 成功路径、失败路径、权限边界和状态恢复的验收步骤；证据指向实际构建、运行记录、收据或人工检查结果。
4. 当前剩余限制、未验证环境和下一依赖任务。不要把本地开发启动、静态页面、模拟成功、目录包验证或部分测试描述为安装态或完整功能通过。

“适合委派”列只给出自然的所有权边界，实际拆分时仍需让每个工作包只有一个负责人；共享仓库中的工作者必须先检查其他改动，不得回退他人编辑。所有实现遵守 [代码质量约定](code-quality.md)：共享类型先进入 contracts，领域规则不依赖 UI/IO，SQLite 持有业务权威，渲染层经受限 preload/DTO 通信。

任何真实模型/provider 请求都须先经过最小凭据、来源/授权、预算、截止时间和取消守卫，包括 PLAN-01 的模型计划候选、LESSON-02 的生成、连接检测、Director/教师以及后续媒体任务。M2 的 guard 工作包是共享实现的交付位置，不是允许更早任务无守卫调用的例外；当前采用人工/固定输入的路径不据此宣称模型能力通过。

来源规则按用途应用：正式学科内容必须经过证据准入；无学科内容的最小连接检测不依赖课程材料审核，仍须受凭据/授权/预算/取消约束；检索和抽取只产出材料或候选，不获得正式发布权限。guard 不能造成“没有已核实知识就无法获取资料或测试连接”的依赖循环。

## 2. 开工基线与当前门槛

产品基线为 Windows x64 Electron 单机备考工作台，OpenMAIC 固定本地版本作为学习空间主要复用来源，桌面壳负责原生权限与随包服务生命周期，学习服务持有领域逻辑和 SQLite。事实类内容须关联用户可定位的来源；AI 只产生候选；真实本人作答与 AI 演示分区保存。运行时、课程编辑和扩展后端的最终边界以规划书与架构决定为准。

目前不能宣称 M0 独立环境签核通过：固定三场景已接通真实上游渲染器、播放引擎及 SQLite 测验/互动提交链路，原 `ClassroomSurface` 的页面加载/重试/取消与 Stage 显示准入分支已复制并实际接线。持久教师会话、已审核讲解、白板/聚焦/激光笔、草案场景/元素编辑和 M1 来源链路已有实现；完整 Director/编辑器、互动/PBL/媒体生成仍保留。PACK-02 独立环境及当前源码目录包/安装验收未通过，不代表 M0 或 M1 整体通过。当前证据及真实剩余工作见待办和上游适配记录。

## 3. M0：安装态真实课堂基线

目标是从桌面生产入口启动真实 OpenMAIC `ClassroomSurface`，使用固定审核材料操作幻灯片、测验和一个互动，保存一条本人提交并在重启后读回，再验证真实课堂被装入 Windows 产物。下列依赖顺序不能合并成“页面能打开”：先锁定和构建上游，理解真实存储调用，再接入桌面与最小业务状态，然后接场景和资产，最后重建并验收安装环境。

DESK-01/CLASS-01 的挂载、UI 和资源适配可以先行准备；但固定测验的真实服务提交依赖 STORE-01 的最小存储/提交实现，因此 STORE-01 的实现子包须在 CLASS-01 联调期间提前协作完成。STORE-01 的最终端到端验收则必须等 CLASS-01 接入真实课堂后执行。这里按可独立审查的子包交接依赖，不要求两个完整任务互相等待；CLASS-01 不得只用 DTO、mock 或静态 UI 作为完成证据。

### 3.3 资产基础之后的具体实施顺序

图片/公式字体基础由项目分区的 SQLite 资产仓库、真实 `HttpAssetStore` 客户端和受保护的绑定接口承接。下一子包按实际上游调用图推进；本节细化 CLASS-01/STORE-02，不新增“完成”状态，也不降低完整课堂门槛。

| 子包 | 实际上游调用位置 | 具体实现与验收 | 所有权与交接 |
| --- | --- | --- | --- |
| 有序课堂运行记录 | `lib/quiz/runtime.ts`、`components/scene-renderers/quiz-view.tsx` | 适配 `createSession/getSession/listSessions/listRecords/appendRecord/setSessionStatus`；按项目和服务绑定的本人/模拟身份分区，校验预期尾序号，审核记录追加与会话完成原子提交；真实客户端覆盖并发冲突、重复提交、重启读回 | 存储与运行路由负责人先交付合同；课堂负责人接入实际测验生命周期。现有 `classroom_state` 播放位置不能代替 RuntimeStore |

## 11. 执行与状态更新规则

- 每个实施包先核对当前源码、合同和上游实际调用方，再改动；不因规划文档猜测接口，也不搬回已删除的历史报告。
- 任务并行前先确定共享文件所有权和 API/DTO/schema；主进程权限、领域判定、SQLite 事务与 iframe UI 不由一个模糊的“课堂接入”包一并承担。
- 使用项目规定的构建和验证入口。生产 HTTP 验收必须由当前源码生成的 learning 产物支持；Electron 目录包和安装包的结论注明各自范围。
- 实现完成后做独立只读审查；审查结果不能由实现者自述代替。发现缺陷先修复并重新验证对应门槛。
- 仅在实现和对应验收均通过后更新待办及 JSON `status/evidence`。局部测试、计划完成、演示录屏或未经干净环境验证的安装包都不是完整阶段证据。
- 每次只推进依赖已满足且可验收的工作包；阻断要写出复现条件、影响面、尝试结果和下一步，不填猜测工期或虚构测试成绩。
