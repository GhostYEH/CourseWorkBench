## 1. 复用结论与产品边界

OpenMAIC 可以作为学习空间的主要代码基线：课堂、教师、AI 同学、白板、幻灯片、测验和互动场景尽量复用。备考知识、材料证据、考纲映射、题目身份、真实作答与错题合同由本项目实现，再接入课堂。课堂负责呈现和组织学习，不能自行成为知识权威。

首批是一间桌面课堂：一名教师、默认零至两名可选 AI 同学、一个实际学习者；先交付“可调参数的二维实验”和“概念关系互动”。最终须支持六类互动、PBL、可配置角色与完整语音能力；3D 可视化不等于另做一个三维教室。语音供应商配置不能成为阅读已发布课堂的前提。

“大部分能引用”应按模块决定，不能估算未经验证的复用百分比。课堂模块的覆盖面很大，但 Web 持久化、模型配置、文件权限、身份、资产路径和部署方式都需要桌面适配。现有上游的检查不等于本项目的来源合同。

## 4. 学习空间的实际学习流程

1. 从计划中的“开始上课”进入，服务检查课程发布版本和所有关联来源；草案只能预览。
2. 展示目标、知识范围、教师、可选同学、预计用时和当前课程版本。用户随时关闭同学。
3. 教师按已审核讲解卡授课，标出来源；需要时调用白板或聚焦当前公式/图形。
4. 进入互动场景，用户调整参数、解释观察、完成预测。教师读取有效观察，并结合本人的文字作答给提示。
5. 独立测验期间默认暂停 AI 同学解答，避免提前暴露答案；用户可以明确请求提示或解析。
6. 用户本人提交后保存不可变作答；系统判分和错因候选分开，不能根据同学回答判定本人掌握。
7. 形成课堂摘要、错题与复习建议。摘要区分本人行为、AI 演示与未完成项。
8. 离开或关闭应用保存检查点；回来继续同一课程版本，等待作答仍保持等待。

可切换“教师讲解”“独立学习”“讨论”三种模式。同学关闭、模型断网或 TTS 不可用时，已发布课件、材料、互动模板和本人作答仍可使用；新生成提示明确显示不可用，不伪造老师正在回复。

## 5. 来源合同怎样覆盖整间课堂

### 5.1 课程、场景与证据侧表

发布流程：`有效知识/来源快照 → 课程提纲 → 场景草案 → 内容/题目/资产检查 → 人工语义审核 → 冻结 stage 文档版本 → 正式课堂`。

建议独立维护下列侧表，避免修改公共 DSL：

| 记录 | 最少字段与约束 |
| --- | --- |
| 课程发布映射 | projectId、lessonId、lessonVersion、stageId、stageDocumentVersion、documentDigest、evidenceBundleId、status |
| 证据包 | knowledgeId + revision、materialId + revision、segmentId、fingerprintAlgorithm/normalizationVersion/fingerprint、审核收据、考纲映射 |
| 场景证据 | stageId、sceneId、sceneRevision、claimId、knowledgeRefs、sourceRefs、reviewReceiptId、status |
| 题目绑定 | questionId、questionRevision、sceneId、originRecordId、出处类型、出处显示文本的生成版本 |
| 运行发言/动作 | sessionId、turnId、actorId、actorType、claimRefs、sceneRevision、动作内容摘要、校验结果 |

来源侧表包含陈述划分与人工审核记录；不能只给整门课挂一个教材文件。互动中的公式、规律、参数含义、适用范围和标准答案均需要知识/来源依据；按钮、坐标绘制逻辑和操作说明可不作为学科陈述，但不能借此绕过审核。

一份发布课程绑定一个冻结的 stage 文档版本。编辑课件后创建新草案，不就地修改正在学习的发布版本。更新材料、知识点或互动代码产生新版本/摘要，标记受影响课程失效；开始课堂、切换受影响场景、老师调用动作与发布输出时均检查。历史内容保留审计，失效部分不继续作为当前教学依据。

### 5.2 课堂教师和同学的动态内容

首版正式授课优先执行已审核讲解卡、例题与白板动作。实时提问允许先生成结构化回复候选，再检查当前知识范围、证据引用、题目身份和权限；流式草稿只显示在待核区域，不能先播语音或写入正式白板再补检查。

已有审核内容的引用/选用可以直接执行。新学科结论、改变条件的改写、新解答和新的教学实验必须走内容审核；证据不足显示“这一点还需要补充材料”，并保留候选入口。范围内的表达改写是否自动放行，是单独的可审计策略，首版默认保守，并抽检语义支持与推理正确性。

检查有效知识 ID 和段落指纹只能证明引用可定位；模型仍可能用真实引用支撑错误结论。对实时生成内容不能宣称程序完全解决语义幻觉。备考闭环先把实时新学科回复作为待核内容，真实课堂运行时中的已审核讲解内容承担连续授课；以后验证语义检查策略后再扩大自动发布范围。此取舍必须在用户界面明确，已审核内容不能作为保留自写静态宿主、跳过实际 ClassroomSurface 的理由。

教师仍可实时选择已审核讲解/提示、追问本人的思路、请求观察和解释、引导下一步操作；不新增学科断言的交互无需逐句人工审批。受控组件中按已批准公式和参数范围计算的数值可由确定性代码核验。既保证实际授课可连续进行，也区分选择/计算已有内容与提出新事实。

若回复提出未知考点，只暂停相关讲解/动作，不销毁整节课。经用户补材料与审核后生成新课程版本，再明确切换；不偷偷更换正在学习的来源包。

### 5.3 攻击入口必须一致

无来源考点分别从备考生成、教师发言、同学发言、白板文字、互动 HTML、题目解析和导入课件注入，均不能进入正式教学。伪装题目出处由可信创建/导入记录判定，不采信模型自报的“真题”。生成材料里的提示指令也不能改变服务工具权限。

离线发布审核同时扫描场景全文、脚本/HTML 可见文本、公式标签和标准答案；运行时追加内容也经过同一领域检查。不能只审核 Markdown 导出而放过课堂画面。

## 6. 教师、虚拟同学与本人数据

| 角色 | 可以做 | 服务明确拒绝 |
| --- | --- | --- |
| 教师 | 选择已审核讲解、给提示、提出候选、在授权范围操作白板/聚焦、等待用户 | 批准知识、伪造出处、代替本人提交、直接改掌握状态 |
| AI 同学 | 提问、比较方法、总结；用户允许后展示模拟推理 | 默认控制课件/清空白板、写本人的答案、冒充真人、形成独立无限聊天 |
| 本人 | 提交真实作答、请求提示、关闭同学、核对材料、人工审核 | UI 也不能把无来源项标成核实通过 |
| Director | 在允许角色/工具范围调度、检查预算、交还用户 | 增加工具权限、绕过知识准入、根据 AI 发言授予掌握 |

上游 `ROLE_ACTIONS` 的 student/assistant 默认带白板动作，本项目不能原样照用。首版同学仅发言；演示白板属于显式能力，开启后仍受白板证据与动作审核。persona 和用户风格输入只是表达偏好，不能授予权限。

每条消息、答案及动作固定记录 `actorType = human_learner | teacher_ai | peer_ai | system`。本人的 learnerKey 来自服务会话，不由页面或角色提交自由字符串。同学模拟作答存为 simulation，不能写进本人 quizAttempt、错题正确率、考纲掌握率或复习完成数。AI 提出的诊断是候选，人工确认或诊断题提供进一步证据。

默认建议：同学一“追问条件”，同学二“比较步骤”；均在角色旁持续显示 AI 同学。讨论由用户优先：用户发言/停止后取消未提交的后续同学轮次。允许有用的错误演示时只能选已审核案例，并显著标注“模拟错误示例”，不能让自由生成的错误自然进入正文。

## 7. 可视化互动与隔离

首版优先制作可重复使用的受控二维组件，减少任意生成 HTML 的审核成本：

| 组件 | 用户活动 | 保存与来源 |
| --- | --- | --- |
| 参数实验 | 改变一个参数、先预测、观察曲线/几何变化、解释原因 | 组件版本、参数快照、预测/解释；公式、范围和结论绑定核实知识 |
| 概念关系 | 连接/排序概念、判断条件、说明关系 | 节点/边版本、本人提交；标准关系与必要条件逐项有证据 |

可选示例可用数学函数单调性等；最终学科与示例由真实材料决定，不能把例子当已核实默认知识。

互动 iframe 保留上游隔离方案，允许脚本运行但不开放 same-origin 能力；自身不能读取 preload、项目文件、密钥或主应用会话。HTML 加严格资源 CSP，只允许审核后打包的资源地址/资产清单。资源协议或回环资产接口必须绑定项目和 iframe 场景授权，不能把原生文件路径交给 iframe。

消息必须验证来自当前 iframe、场景/组件实例、课程版本、序号及新鲜度，限制载荷大小和频率；不能仅检查 `origin`，因为隔离 iframe 可呈现 null origin。观察文本视为用户/组件输入，不能携带或获得工具权限。浏览器自报“已完成”“答对”不是可信判分；有标准答案的组件由服务验证本人提交，开放实验以行为记录和自我解释评价。

保活只负责同一次应用进程中切换场景时保持状态。跨进程恢复只支持实现 `snapshotVersion + exportState/importState` 的受控组件，保存前验证 schema；不支持者明确显示“实验已重置，预测和作答记录已保留”。不序列化整个 DOM、闭包、iframe localStorage 或任意 JS 执行位置。

## 8. 持久化适配与恢复合同

本地 Next 服务是唯一数据库写入者。OpenMAIC 的前端 HTTP adapter 可以保留接口形状，后端实现下面合同，并保持项目授权与版本规则：

| 合同 | SQLite / 本地目录的责任 |
| --- | --- |
| DocumentStore | stage/scene 聚合、DSL 版本、文档版本冲突、删除/归属规则 |
| RuntimeStore | 真实 learnerKey 分区、会话状态、追加记录、CAS 序号检查；不能跨分区读写 |
| AssetStore / AssetByteStore | 资产元数据、引用、内容摘要、本地字节、一致性删除与路径边界 |
| KV | 非事实偏好和视图状态；不把掌握/知识发布藏在 KV |
| AgentSession 合同 | 实际开启的生成后台任务生命周期、事件日志、条目与投影；验证孤儿恢复与取消语义 |
| 本作品侧表 | 来源、知识权威、发布映射、本人作答、审核收据、去重/事件 outbox |

前端 store 从服务恢复；IndexedDB/localStorage 只是缓存。原上游存储版本、schema 迁移和异常语义需通过合同测试，不只实现“能 save/load”的薄层。首版不启用的 Material/Skill 持久化功能需显式禁用；启用时按实际调用图补适配，不能回落到另一份浏览器权威数据。

课堂持久会话至少记录：项目/打开代次、发布课程与来源版本、实际 learnerKey、sceneId、playback checkpoint、role config version、等待类型、已提交发言/动作序号、quiz 草稿/提交 ID、白板版本、互动组件快照、预算累计与终止原因。

恢复按四层分开验收：

1. 文档层：同一冻结课程版本和场景顺序。
2. 讨论/白板层：已提交消息与动作，无重复执行；未提交模型草稿可丢弃并显示原因。
3. 作答层：本人的草稿、不可变提交与等待类型；AI 同学不进入该层。
4. 互动层：受控组件快照可恢复；未知组件明确重置。

上游 Director 是请求级循环，新增外层持久 session 协调器，不能将当前 HTTP 请求自然结束当作整节课完成。连接中断后通过收据/序号查询再恢复，不直接重放动作。模型请求可能重试，但业务提交唯一；异步跨合同更新使用事务或 outbox/幂等消费者。

## 9. 编排预算与响应体验

沿用规划书备考生成预算；课堂一轮默认总计最多 4 次模型调用、2 次同学发言，教师/Director/同学共同计数，并限制累计 token/时间/动作数。课程累计预算另设，不能让每轮重置带来无限成本。具体 token/延迟目标在 M2 小样本试跑后冻结。

独练时禁止抢答，老师等待本人提交。等待审核、作答或材料时结束模型轮次；再次调用需要新的明确输入。关闭同学只影响后续轮次，历史讨论保留 AI 标签。停止按钮能终止未提交调用/动作，已提交记录继续存在。

课程来源检查不依赖联网；断网仍可阅读已发布课件和离线互动。加载状态分别显示“服务启动”“课件加载”“教师准备”“等待你作答”，不使用一个永远递增的百分比。

## 10. 复用与验收的完成条件

M1—M4 备考闭环必须有实际运行记录证明：安装后的真实 ClassroomSurface、教师讲解、白板、两种互动、本人测验、可关闭 AI 同学、来源侧表、错题回流和重启恢复均可工作。图片/字体/头像资源不需要开发服务器或未声明的远程地址。最终产品还须满足 A—F 和全部 85 项能力，两种基础互动不能替代六类互动、PBL 或完整编辑/媒体/Pro 能力；阶段关系见[规划书](规划书.md)。

核心失败用例包括：伪装真题、无来源白板/同学发言、过期材料场景、iframe 消息伪造、重复提交、旧项目模型响应、崩溃后的重复动作、同学答对却本人未作答。样本固定并可重算；已审核场景机械证据覆盖建议目标 100%，语义正确性通过人工抽检另报。
