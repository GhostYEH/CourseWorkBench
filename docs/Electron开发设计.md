## 1. 技术方案

首版采用 Electron 桌面壳 + 一个随应用启动的本地 Next.js 服务，Windows x64 优先。工作台与 OpenMAIC 学习空间同属一个 React/Next.js 应用；复用其课堂组件、API 和教学编排，新增备考页面与领域服务。本地服务统一拥有 SQLite，Electron 主进程不另开数据库写同一事实。

这是对 v0.2 规划中“Vite 静态界面、主进程直接运行全部业务”的替代决定。采用单一本地应用避免同时维护 Vite 工作台、Next.js 课堂和跨页面 iframe 消息协议。组件迁移到 Vite 是候选方案，仅在 M0 实际试验表明当前方案存在阻断时按 ADR 比较评估，不并行开发两套生产入口。

| 部分 | 选择 | 目的 |
| --- | --- | --- |
| 桌面容器 | Electron | 窗口、文件选择、系统主题、主进程与安装交付 |
| 应用层 | OpenMAIC 基线的 React/Next.js + TypeScript | 备考页面与 ClassroomSurface 同一个应用，不重写完整课堂 |
| 构建 | Electron main/preload 构建 + Next.js standalone | 生成桌面壳和随包本地服务 |
| 服务运行时 | 随包 Node，满足上游 >=22.19.0 及选定依赖要求 | 用户无需另装 Node；避免把 Next 服务绑定 Electron Node ABI |
| 数据 | SQLite；实际驱动 node:sqlite，better-sqlite3 仅为替换候选 | 事务、版本检查、提交去重和本地恢复 |
| 数据校验 | 共享运行时 schema | IPC、模型结构和领域提交校验 |
| 文本 | Markdown 编辑/预览组件 | 阅读讲义与编辑候选，代码块保留等宽字体 |
| 视图状态 | 复用 OpenMAIC 的 Zustand store，增加工作台视图 store | SQLite 为持久记录，浏览器缓存不作为唯一恢复来源 |
| 图标 | 一套本地打包的线性图标 | 保持尺寸、线宽与无障碍名称一致 |
| 分发 | electron-builder；Windows NSIS | 安装、启动、升级和卸载验证 |
| 检查 | 类型检查、领域单元测试、Electron 窗口测试 | 验证核心约束、恢复与实际安装产物 |

依赖版本先冻结 OpenMAIC 的本地 lockfile、相关包及实际采用文件摘要，再验证与 Electron 壳的组合；M0 基线试验避免同时升级框架和大范围改动复用代码。本地数据库驱动运行在独立 Node 服务，原生依赖须匹配该 Node 的 ABI；Electron 主进程若日后增加原生模块，再单独验证 Electron ABI。[Electron 原生模块说明](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)

OpenMAIC 的 `next.config.ts` 已设置非 Vercel 构建使用 standalone。安装产物必须包含 `public`、`.next/static`、workspace 包、动态模块、技能文件与必要字体，不能只搬一个 server.js；Next.js 不默认把 public 与静态目录复制进 standalone。[Next.js output 官方说明](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)

首版按材料/段落编号和文本检索组织上下文，无需向量数据库、Python 服务或 Docker/PostgreSQL。多角色课堂使用 OpenMAIC 自带调度，DSH/EvoFlow 仅补充设计参考，不能再叠加完整运行时。

## 2. 进程与权限分层

```text
Electron Main：窗口、文件选择、凭据、项目打开代次、子服务生命周期
    ↓ 有限 IPC / 父子初始化通信
Preload：原生文件授权、窗口/凭据配置等白名单方法
    ↓
Renderer：同一本地应用中的备考工作台 + OpenMAIC 学习空间
    ↓ 已认证的同源 HTTP / 流事件
本地 Next.js 服务：来源准入、SQLite、模型、课堂与会话
    ↓
项目数据库 / 不可变材料与资产 / 用户配置的模型
```

Electron 主进程拥有原生权限，本地服务拥有领域事实。渲染进程不能直写数据库、读取任意文件或得到模型密钥。主窗口显式启用 contextIsolation 与进程沙箱，禁用 Node 集成；preload 逐项暴露原生方法，不提供任意 invoke/send。内层模型生成互动 iframe 不获得这些原生能力。[Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[Process Sandboxing](https://www.electronjs.org/docs/latest/tutorial/sandbox)

主进程验证 IPC 调用方、主框架、参数与项目打开代次；本地服务验证应用身份、项目及领域权限。普通 Markdown 不执行 HTML/脚本；可执行互动 HTML 仅在专用沙箱 iframe 内运行，不能混入普通文档。导航、新窗口和外链执行独立检查。[Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)

数据库访问放在本地服务的串行仓储层。课程/场景生成与课堂流共享领域准入，但生命周期分别记录；网络请求异步执行，较重计算使用受控工作线程，不能堵塞本地健康检查与取消请求。

### 2.1 本地服务启动与身份

1. Electron 从受控资源目录启动随包 Node，以参数数组启动子进程，不使用 shell 拼接路径；Windows 后台进程隐藏窗口。
2. 服务只监听 `127.0.0.1`，分配可用端口；父子通道回传真实端口与随机服务身份，不能预占端口后释放再假定未被抢占。
3. 主进程确认进程与健康握手后，为当前 Electron 会话建立不可脚本读取的应用会话凭据；凭据经受控父子通道传递，不放 URL、日志或 NEXT_PUBLIC 配置。
4. 服务校验会话、Host 和修改请求的 Origin/CSRF 边界；回环地址不是免认证理由。健康端点只返回无敏感的就绪状态。
5. 窗口只加载已握手的准确本地 origin；preload 的原生方法只接受该窗口主框架，内层 iframe 和外部页不能调用。
6. 退出先停止新任务、保存检查点、关闭数据库，再停止本应用启动的子进程。服务崩溃显示离线与恢复入口，不能把丢连接当作任务已取消。

应用 origin 的端口变化会影响 IndexedDB/localStorage，因此浏览器存储只用于非权威缓存；项目与外观偏好通过本地服务/主进程持久化，课堂 store 使用本地存储适配恢复。备份范围不包含短期应用会话凭据。

## 4. 项目目录与配置位置

用户通过原生目录选择器创建或打开项目。主进程保存项目身份和打开代次，通过受控通道将已授权目录交给本地服务；渲染层只持项目 ID 和绑定标识，不能向 HTTP API 提交任意磁盘路径。

```text
用户选择的项目目录/
├── project.json                 格式版本、项目 ID 和显示名称
├── .study/
│   ├── study.db                 权威知识点、证据、作答、会话与收据
│   ├── sources/                 不可变版本的原始/规范化材料
│   └── assets/                  本地课堂图片、互动资源和可选音频
└── exports/                     导出的 Markdown 与 JSON
```

项目目录内的 manifest 只承载身份与格式说明；目标、日期、计划和知识点等领域事实统一在数据库中维护，避免 JSON 与数据库双写同一事实。

全局配置在 userData 中持久保存：主进程负责窗口、最近项目和凭据；本地服务负责阅读、主题和课堂视图偏好，各字段只有一个写入者。学习目标、角色和教学表达设置属于项目。主进程加密保管模型凭据，模型请求由本地服务执行，只在运行期间经受控父子通道得到必要凭据；不下发到页面、不进入项目备份。

凭据通过 Electron 的平台凭据加密能力保护，具体使用锁定版本支持的 safeStorage API；加密服务不可用时使用会话内密钥，并明确不持久保存。接口在 Electron 版本间可能变化，实现时以选定版本为准。[safeStorage 官方文档](https://www.electronjs.org/docs/latest/api/safe-storage)

首次打开项目校验格式与数据库 schema；升级迁移前做一致性备份。较新格式的项目用明确错误说明，不能尝试降级覆盖。项目材料删除采用显式领域操作，禁止绕过引用检查直接移除被教学内容使用的证据。

## 5. 原生 IPC 与领域 HTTP 合同

原生 IPC 用于窗口、目录/文件选择、授权、凭据配置与服务控制；知识/审核/计划/课程等通过同源 HTTP 领域接口进入。入参统一按对象与 schema 校验，响应带结果或错误码。取消选择是正常取消；SQL、任意路径和可执行工具脚本不作为接口入参。

| 方法族 | 用途 | 必须检查 |
| --- | --- | --- |
| `project.create/open/close` | 原生选择目录，建立项目会话 | 调用窗口、目录选择结果、格式与打开代次 |
| `materials.import/readSegment` | 原生选择材料、登记版本、读指定片段 | 材料类型、大小、项目范围和段落归属 |
| `knowledge.propose/listCandidates` | 保存候选和查看待审列表 | 结构、来源 ID、项目归属 |
| `review.preview/apply` | 预览及人工确认知识/计划/课程/错因 | 原版本、引用有效性、事务提交 |
| `study.start/submitAnswer` | 开课和保存实际作答 | 知识准入、题目版本、提交去重 |
| `runs.status/cancel/resume` | 任务查看、取消和恢复 | run ID、项目绑定、终止与等待状态 |
| `exports.save/backupProject` | 原生选择导出目标与一致性备份 | 输出类型、范围、快照状态 |
| `preferences.read/save` | 外观、阅读与教学表达配置 | 设置范围、值域、配置版本 |
| `models.configure/test` | 主进程配置连接、测试可用性 | 参数范围，密钥不返回给页面 |

上表描述逻辑方法族，不意味着所有方法都通过 IPC 暴露。知识和学习业务使用 `/api/study/*` 新入口；OpenMAIC 的课堂/聊天/测验 API 保留路由形状，在服务边界接身份、证据包与存储适配。新增课堂入口为 `classroom.link/open/submitInteraction`，通过当前课程发布版本校验。

用户审核与 AI 工具权限在本地服务分开：review.apply 只通过经验证的界面操作进入，不能注册进备考或课堂 agent 工具列表；所有后台入口使用同一准入，不存在“课堂生成特权”。

项目切换后，旧请求、候选审核卡及模型响应携带的打开代次失效。请求即便返回，也不能写进重新打开的项目。支持同路径重开时重新分配代次，不能只按目录字符串判断身份。

## 6. 桌面中的 harness 生命周期

工具与来源合同继承规划书。本地服务创建备考 run 与课堂 session，冻结知识、材料、计划、课程、教学表达及角色版本；UI 接收已校验的草案、进度与等待状态。Electron 管理服务，不充当第二个业务运行器。

事件至少包括：`run_started`、`step_started`、`draft_delta`、`proposal_created`、`review_required`、`answer_required`、`step_committed`、`run_completed`、`run_failed`、`run_cancelled`。每项携带项目身份、run ID、步骤 ID 与递增事件序号。

流式文字只展示为“生成中的草案”，不能作为已发布课程或已保存知识点。正式提交后刷新本地服务读取的权威结果；页面重新加载时从快照和事件序号恢复，不靠拼接缓存重建事实。新学科回复的草稿不提前写入正式白板或播放语音，已审核讲解卡承担首版连续授课。

备考助手、课堂讨论和任务面板分别显示关联运行，使用共同项目及学习会话身份。切换标签不停止任务；切换项目先停止新生成并保存/取消旧任务，首版同时只打开一个可写项目。课堂离开时保存场景/动作位置，UI 不自己判定知识掌握。

等待审核或作答时结束当前模型轮次并持久保存等待。课堂教师/同学共享回合预算，不持续互聊。现有 OpenMAIC Director 包含请求级编排，不能直接认为已具备桌面重启恢复；外层添加持久课堂会话和事务收据，再调用其编排函数。

退出时，存在尚未提交的作答草稿或正在执行的任务则显示保存并退出、停止并退出、继续使用等明确选项。保存在数据库中的草稿不计作真实提交；已提交业务结果保持有效。首版不承诺关闭应用后后台继续运行，重启通过检查点恢复。

预算、业务去重、来源失效按规划书。恢复区分课堂文档、聊天/白板、本人答案和互动临时状态；iframe 保活不保证任意实验跨进程恢复。教室会话不得将 AI 同学作答写成 learnerKey 对应的本人提交。事件接收后只按已提交序号恢复；连接中断不自动重放已经执行的动作。

## 7. 桌面交互与快捷键

默认窗口建议 1440 × 960，最小 1024 × 640；恢复上次尺寸与位置，并校正到当前可见显示器。标题栏采用自有工具栏，窗口拖拽区域与按钮交互区分离。

Windows 首版验证最小化、最大化、双击标题栏、系统缩放与多显示器恢复。若自定义标题栏出现兼容问题，可先用原生窗口装饰加应用工具栏完成交付。

| 快捷键 | 行为 |
| --- | --- |
| `Ctrl+N` / `Ctrl+O` | 新建 / 打开项目 |
| `Ctrl+S` | 保存当前可编辑草稿；不能批准候选 |
| `Ctrl+F` | 当前文档查找 |
| `Ctrl+Shift+F` | 项目材料与知识点搜索 |
| `Ctrl+Enter` | 明确处于作答输入区时提交答案；其他表单按按钮定义 |
| `Ctrl+Shift+E` | 导出当前或指定产物 |
| `Ctrl+加号/减号/0` | 界面缩放 / 恢复 100% |
| `Escape` | 关闭当前临时弹窗或抽屉，不默认为取消模型任务 |

快捷键须提供菜单入口。全局快捷键不拦截文本控件中的常规输入；焦点、弹窗和当前任务决定实际行为。每次破坏性操作用具体对象名称描述影响。

## 8. 外观与教学表达的持久化

外观配置采用有版本的白名单对象，支持纸色/浅色/暗色/跟随系统、强调色预设、字体、阅读字号/行距、缩放、密度与面板布局。用户明确选择的主题在升级后保持不变。

界面缩放使用一个统一缩放机制；阅读字号仅作用于正文，不与另一套全局字号缩放重复叠乘。面板拖动后重新计算宽度与折叠状态，保证正文和审核操作能访问。

教学表达配置分为学习模式、解释方式、提示深度和练习配比，课堂配置另含老师风格、同学数量/参与度、白板、可视化和可选语音。开始 run 或课堂轮次时冻结其版本。主题适配只修改上游 UI 层，保持课件坐标、题目内容与来源合同。

外观设置保存成功、项目草稿保存成功、审核通过和正式发布是不同事件，顶栏不能用同一个“已保存”让用户误解。主题切换不改变课程内容和掌握记录。

## 9. 导入、导出与备份

导入首阶段为 txt/md，文本 PDF 随解析与段落定位验收接入。原生选择发放操作/路径范围受限的授权，服务读取已授权文件；不接受来自课堂 iframe 的磁盘路径。PPTX/HTML 课堂导入先列为候选，导入上游课程不自动获得本作品的来源核实状态。

导出依据权威记录渲染 Markdown 和 JSON。候选另放在明确的待审核输出中，禁止与已发布课程混放。对导出目标已存在的文件提供可辨认的覆盖或另存选择。

备份包含 manifest、数据库一致性快照、证据材料和所引用的本地课堂资产，保留 DSL/schema 版本、审核与提交收据。启用 WAL 时，不能只复制运行中的 `.db` 文件；通过驱动支持的一致性备份或关闭写入后复制。资产/材料导入期间取得一致版本，避免数据库引用的字节尚未复制；恢复先在临时目录检查 schema、资产摘要、来源指纹和外键，再切换项目。

应用卸载与升级不主动删除用户项目和备份。项目备份不等于 Markdown 导出；Markdown 无法恢复所有审核收据、原始材料和运行记录，界面分别命名。

## 10. 开发里程碑与安装验收

真实课堂、固定三场景、本人提交重启读回以及备考来源/计划/课程、教师/基础互动、反馈/恢复工具和在线协作软件链路已部分落地。M0 的当前源码安装态与独立环境门槛尚未通过，后续软件子项不替代该门槛。M0—M4 仅定义备考闭环，最终 85 项能力按 A—F 另行追溯和验收；不沿用旧的 10—12 周全功能估算。具体输入、依赖、实施包与验收见 [开工任务清单](开工任务清单.md)，完成定义见[规划书](规划书.md)。

必须完成的检查：

- 领域检查：无来源、错指纹、材料失效、错误题目身份、模拟作答与重复步骤均按合同处理。
- IPC 检查：非法参数、过期项目身份和非授权调用不能改变事实；切换项目后旧响应不能提交。
- 窗口检查：知识审核、来源跳转、作答、关闭保护、重启恢复和键盘操作形成完整闭环。
- 视觉检查：三套主题、100%/125%/150% 系统显示缩放、1024 × 640/1280 × 800/1440 × 960 窗口及界面 80%/100%/125%/150% 缩放均检查关键页面。缩放后的低有效宽度应自动折叠辅助面板。
- 安装检查：没有开发 Node 环境的 Windows 机器能安装、启动、读写项目并导出；检查原生 SQLite 依赖、中文和带空格目录、断网打开历史课程及卸载保留数据。
- 凭据检查：密钥不出现在渲染状态、日志、评测导出与项目备份中；主进程加密不可用的行为可验证。
- 本地服务检查：回环地址、身份握手、端口变化、静态字体/头像/动态模块、服务崩溃和优雅退出；用户未安装 Node 时仍可运行。
- 课堂检查：真实教师、AI 同学开关、白板、二维实验、概念互动、本人答案与场景证据；未知/过期互动报告不能授予掌握。

首版交付开发/打包命令说明、安装包及真实安装记录。没有实际执行安装验证时，明确标为尚未验证。macOS/Linux、自动更新、签名与公证属于后续发布里程碑；首次作品交付可提供手动安装升级路径。
