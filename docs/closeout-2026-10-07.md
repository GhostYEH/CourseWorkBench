## 本轮已实现的软件行为

- 协作协议升级至 **5**。板书先由房主提交 `review-board-content` 人工语义确认，权威服务保存陈述、正文、审核人、场景及事件回执。`write` 必须引用完全匹配的 `reviewEventId`，有效陈述 ID 本身不能批准新正文。修改正文、跨场景、非房主、等待本人均不能绕过准入。
- 白板的文字、公式和简图统一使用共享 renderer。SVG 呈现真实端点、方向和关系标签；短边保持方向，重合节点明确说明未绘制连线，自环单独呈现，同页 marker 唯一。旧状态继续可读，旧动作不会获得虚构的审核回执。
- 数据库 **v34** 增加公共 AI 状态。候选、房间 revision、事件序号与幂等收据原子提交，读回核对 SQL 身份和内容摘要。场景切换清空当前场景的板书审核与 AI 状态。
- 房主可手动生成一次教师说明或 AI 同学发言。真实配置运行时经过本地主入口；只有本地已审核发布课程中的匹配冻结陈述、有效来源、确认 run、正式同学角色和共享预算允许时才派发 provider。公共提示不包含个人答案和评分依据。
- 生成结果只进入房主待核区。人工批准和明确播报是两个独立操作；对端只读已播报的 AI 白名单投影，包含 AI 标识、依据陈述和条件，不含模型标识、审核批注和待核正文。房主与成员看到相同公共投影。
- 本地用量台账在远端登记前保存 provider 结果。远端响应丢失后重试沿用原命令、候选 ID 和结果，不重复付费；未确认的模型结果不自动再次调用。失败、取消和未知用量仍保留相应调用和预占。
- 等待期间不发起模型调用；执行中通过权威状态 watchdog 中止等待、场景变化或无法确认的调用。用户取消及项目作用域变化可中止尚未完成的候选 HTTP 传输，结果读回也再次复验作用域。
- 升级前未确认的 v4 板书写入隔离保留，不能自动按 v5 重放。提示保留房间、场景、事件标识并提供查看房间入口；本人明确确认才清理对应请求，其他命令不受旧记录阻塞。

人工 `semanticReviewed` 是房主核验事实、来源与适用条件的声明，程序不会自动证明任意正文语义正确。公共 AI 的关键词过滤属于辅助防护，不能替代人工审核。独立协作服务的 `origin: model_generated` 记录经过房主本人认证的 gateway 声明，不能证明外部 provider 确实发生调用；有效房主凭据可以在专用入口提交 pending 候选。模型调用证据和用量保存在本地台账。

取消只覆盖远端事务尚未提交的窗口；远端已经接受的事务不承诺回滚，靠原请求收据去重恢复。已播报内容仍必须经过权威审核路径。
