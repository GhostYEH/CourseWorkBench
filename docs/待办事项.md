## 代码接口与结构整改（剩余）

| ID | 剩余工作 | 验收动作 |
| --- | --- | --- |
| N1 | 客户端 `apiFetch<T>` 仍对 JSON 响应直接断言；补齐实际响应的运行时 schema 验证 | 错误 envelope 与不符合 DTO 的响应不能被当作合法结果；真实 HTTP payload 与共享合同一致 |

| N8 | 为计划、运行快照及步骤收据等实际消费的 JSON 数据补齐领域形状与版本校验，消除泛型读取后直接断言 | 合法 JSON 中的非法字段、数组或错误根类型可诊断拒绝或显式降级；恢复不消费损坏收据 |
| N9 | 补齐 lint/格式化策略与 CJS 语义检查；完善模块依赖规则 | 门禁覆盖声明及实现边界，不以语法检查替代语义检查；避免整仓无关格式化 |

## 必须持续覆盖的合同场景

- 无来源候选不能进入权威知识或正式教学；引用存在但不支持时拒绝发布。
- 未授权或旧项目请求拒绝；来源版本替换后关联场景暂停/失效并可重新审核。
- 新编题自称真题不能获得真题身份；AI 同学答案只写入 simulation。
- iframe 伪造高分不能直接判分；提交后响应前崩溃恢复既有提交且不重复计数。
- 已提交白板动作断连后不能重复执行；不支持恢复的互动明确重置且不丢已保存本人答案。
- 端口/会话变化不复用旧授权；模型断网或预算耗尽明确失败/等待，不模拟进度。
